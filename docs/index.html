Overview

ANGRY is one website with separate product modules. Users can move between Tracker, Token Creator, NFT Creator and Docs without feeling like they are visiting unrelated projects.

The code remains separated by product. This is intentional: a change to the NFT Creator should not require rewriting the Tracker, and a Tracker update should not risk breaking token deployment.

$ANGRY and the tools are not the same thing. The token can remain a meme token while ANGRY products are developed as separate research and creator tools. Holding a token should not be presented as ownership of product revenue unless that is explicitly and legally implemented.

ANGRY Tracker

The Tracker is built to reduce the number of separate pages a user must open when researching a token. It combines market information with modular checks that explain the evidence they found.

Current analysis modules

  • Token overview / checker
  • Token burn tracking
  • Liquidity analysis
  • Holder concentration
  • Creator / deployer review
  • Creator history
  • Wallet relationship and funding trace
  • Risk timeline
  • KOL / promotion activity
  • Cross-token / developer relationship comparison
Important: a signal is not proof of fraud. KOL activity, wallet overlap, concentration or other observations need context and should be presented as evidence for the user to review.

Token Creator

The Token Creator guides a user through network selection, contract type, token name, symbol, supply and deployment review.

Standard Token

The current Standard Token beta has no token tax, no extra mint function and no admin controls in the precompiled deployment path. The full initial supply is minted once to the deployer wallet.

When this feature is eventually enabled, ANGRY can create and launch the NFT asset. Animation, game logic, 2D/3D models, inventory behavior and in-game integration remain the game developer's responsibility.

Network Architecture

EVM networks

Ethereum, Base, Robinhood Chain, BSC, Arbitrum and Polygon use EVM-compatible smart-contract and wallet patterns. Individual ANGRY tools can still have different readiness on each network.

Solana

Solana is not an ERC network. Token creation uses Solana token programs and Solana wallet instructions. NFT deployment also requires a Solana-specific NFT path. ANGRY should keep this implementation separate instead of pretending ERC-20 / ERC-721 / ERC-1155 logic works on Solana.

Fees & Gas

Blockchain network gas is separate from any ANGRY platform fee. Gas is paid to the network through the user's wallet.

Current beta: platform-fee rules are not finalized across the products. Do not publish a permanent fee schedule until the exact on-chain calculation, treasury destination and disclosure are implemented and verified.

Security & Testnet Rules

  • Test deployment before enabling mainnet.
  • Never put private keys or wallet recovery phrases into the website.
  • Do not expose secret provider API keys in static GitHub Pages JavaScript.
  • Show the selected network and contract settings before wallet approval.
  • Keep planner-only features visually different from deployment-ready features.
  • For NFT artwork and metadata, use permanent storage before live minting.
The safest release pattern is: configure → review → testnet deploy → verify contract behavior → only then consider mainnet.

Creator Responsibility

Creator tools should make responsibilities clear rather than promising that ANGRY verifies ownership of every asset or business claim.

  • NFT creators should confirm they own or have permission to use uploaded artwork.
  • Token creators are responsible for the project information and settings they choose.
  • Future ticket issuers should confirm they are authorized to issue tickets for the event.
  • Game developers are responsible for connecting NFT ownership to actual game functionality.

Roadmap Principle

ANGRY should add features step by step rather than marking unfinished mechanics as live. Stable product pages can be frozen while new functions are developed in separate versions.

A practical order from the current build is:

1. Stabilize unified navigation and Tracker 2. Verify Standard Token deployment on each enabled testnet 3. Add permanent NFT storage 4. Add real ERC-721 / ERC-1155 NFT testnet deployment 5. Build a proper Solana token/NFT path 6. Revisit Event Tickets and other Coming soon NFT modules 7. Add API documentation when API access is actually available
